# 기술 블로그 스택별 용어 풀이·비유 모음

기술 블로그 스타일의 핵심은 "용어를 나오기 전에 쉽게 푼다"이다.
자주 쓰는 스택 용어를 미리 한 줄 풀이 + 비유로 정리해둔다. 글 쓸 때 그대로 가져다 쓴다.

> 이 표는 출발점이다. 글마다 맥락에 맞게 다듬는다. (똑같은 비유를 모든 글에 복붙하지 않는다.)

## Java / Spring Boot

| 용어 | 한 줄 풀이 | 비유 |
| --- | --- | --- |
| Bean | Spring이 대신 만들어 관리해주는 객체 | 직접 조립하지 않아도 필요할 때 꺼내 쓰는 부품함 |
| 의존성 주입(DI) | 필요한 객체를 직접 만들지 않고 Spring이 넣어주는 것 | 요리할 때 재료를 직접 사오지 않고 누가 손질해서 가져다주는 것 |
| AOP | 핵심 로직과 별개로 공통 처리(로깅·트랜잭션)를 끼워넣는 기법 | 모든 출입문에 자동으로 붙는 CCTV |
| `OptimisticLockingFailureException` | 같은 데이터를 동시에 고치려다 충돌이 났을 때 나는 예외 | 같은 문서를 두 명이 동시에 저장 누르면 한쪽이 튕기는 상황 |

## 데이터베이스 (Oracle / MySQL / PostgreSQL)

| 용어 | 한 줄 풀이 | 비유 |
| --- | --- | --- |
| 인덱스 | 원하는 행을 빨리 찾도록 미리 만들어둔 색인 | 책 뒤의 "찾아보기" 페이지 |
| `MERGE INTO` | 있으면 수정, 없으면 삽입을 한 번에 처리하는 구문 | "있으면 갈아끼우고 없으면 새로 넣어줘" 한마디 |
| 멱등성(idempotent) | 같은 작업을 여러 번 해도 결과가 같은 성질 | 엘리베이터 버튼을 다섯 번 눌러도 한 번 누른 것과 같음 |
| 트랜잭션 | 여러 작업을 "전부 성공 아니면 전부 취소"로 묶는 단위 | 계좌이체: 출금과 입금이 둘 다 되거나 둘 다 안 되거나 |

## Kafka

| 용어 | 한 줄 풀이 | 비유 |
| --- | --- | --- |
| Topic | 메시지가 쌓이는 이름 붙은 통로 | 주제별 단체 대화방 |
| Partition | Topic을 나눠 담아 병렬 처리하게 하는 칸 | 은행 창구를 여러 개 열어 줄을 나누는 것 |
| Consumer Group | 메시지를 나눠 처리하는 소비자 묶음 | 택배를 구역별로 나눠 배달하는 기사 팀 |
| Offset | 어디까지 읽었는지 표시하는 위치값 | 읽던 책에 끼워둔 책갈피 |
| Rebalancing | 소비자가 늘거나 줄 때 담당 구역을 다시 나누는 것 | 배달 기사가 빠지면 남은 기사끼리 구역을 다시 분배 |

## Redis

| 용어 | 한 줄 풀이 | 비유 |
| --- | --- | --- |
| 캐시 | 자주 쓰는 값을 빠른 곳에 미리 올려두는 것 | 자주 쓰는 양념을 싱크대 앞에 꺼내두는 것 |
| TTL | 데이터가 자동으로 사라지는 만료 시간 | 우유 유통기한 |
| 분산 락 | 여러 서버가 동시에 같은 작업을 못 하게 막는 잠금 | 화장실 문 잠금 — 한 명 들어가면 밖에서 못 엶 |

## 인프라 (Kubernetes / 모니터링)

| 용어 | 한 줄 풀이 | 비유 |
| --- | --- | --- |
| Pod | 컨테이너를 담아 실행하는 가장 작은 단위 | 한 명이 들어가는 1인용 작업 부스 |
| `emptyDir` | Pod가 살아있는 동안만 쓰는 임시 저장 공간 | 회의 끝나면 지워지는 화이트보드 |
| Prometheus | 지표를 수집·저장하는 모니터링 도구 | 매 순간 계기판 수치를 적어두는 기록원 |
| Grafana | 수집된 지표를 그래프로 보여주는 대시보드 | 기록원이 적은 수치를 보기 좋은 차트로 그려주는 화면 |

## 쓰는 법

글에서 용어가 처음 나오면 이렇게 붙인다.

```
Kafka에서는 메시지를 여러 칸에 나눠 담는데, 이 칸을 파티션(partition)이라고 부릅니다.
은행 창구를 여러 개 열어 줄을 나누는 것과 비슷합니다. 창구가 많을수록 동시에 더 많은 손님을 처리할 수 있죠.
```
